考勤月度核对（追觅类）

attendance-monthly-reconcile
🔁
入口与编排 skills/attendance/
把 HRO 外包场景下「数据员考勤表 → 员工核对 → 问题跟进 → HR 审核包」的月度流程标准化。本 skill 负责流程编排与八阶段门禁（阶段 0–7，不可跳门）；数据归档交 data-prep、异常清单交 exception-review、备注生成交 remarks。从追觅考勤组操作录屏蒸馏，覆盖 80% 飞书打卡场景。

PHASE GATES

阶段门禁（必须按序）阶段 0–7 · 八阶段 · 不可跳门
  1. 0
    花名册与考勤部门GATE
    每人有「考勤部门」列（HR 维护，非原始字段）；职位与 HRO 按身份证号已核对。新增员工对比本月各表 vs 上月，出现在哪张表即属该考勤部门。产出 reference_roster.xlsx。
  2. 1
    原始表备份 + 补字段GATE
    数据员表整表复制保留原始版；working copy 用 VLOOKUP 花名册补身份证号、职位。
  3. 2
    先对人头GATE
    只统计人数与花名册比对、记录差异，此阶段不改任何考勤数据。
  4. 3
    整理数据员表（发员工前）GATE
    隐藏求和为 0 的列；请假只留事假/调休；调休假天数加入实际出勤；迟到早退首次发放前不扣。
  5. 4
    按人截图发放GATE
    截员工行到「总计」列（含按日明细）+ 附「画数」汇总模板，飞书/微信发送。每人已发「个人切片 + 画数」。
  6. 5
    问题跟进GATE
    仅处理反馈有问题的员工：加班、夜班、公出、迟到、事假（细则见下）。改表标黄 + 批注。
  7. 6
    二次确认GATE
    改表后必须员工回复「核对无误」才闭环。
  8. 7
    审核包GATE
    问题员工 Sheet 附改表截图 + 原始确认 + 飞书凭证一并归档；无问题员工保留「核对无误」文字即可。

RED LINES

门禁红线 · 禁止
禁止
  • 未做人头核对就改数据。
  • 未首次发放就预扣迟到。
  • 未员工确认就提交 HR。
▤

STAGE 3 DETAIL

阶段 3 整理细则
按序执行
  • 3.1 隐藏求和为 0 的列（严重迟到、旷工等本月无数据列）。
  • 3.2 请假列只保留：事假、调休假（其余隐藏）。
  • 3.3 调休假天数 += 实际出勤天数（系统实际出勤不含调休）。
  • 3.4 迟到早退：首次发放前不扣，等员工反馈。
参考列 / 不做
  • 参考列：应出勤天数、实际出勤天数、事假、调休假、工作日/休息日/节假日加班、关联调休、不关联调休、按日明细列。
  • 不做：预核加班、预处夜班/公出。
⌖

STAGE 5 DETAIL

阶段 5 问题跟进细则
5.1 加班飞书考勤日历截图
  • 按考勤部门查班次规则（见 rules_catalog_draft.md）。
  • 工作日加班 = 实际下班 − 规定下班 − 晚餐 0.5h。
  • 周末看「小月亮」+ 加班申请「是否关联调休」：是 → 整天计入关联调休；否 → 计入不关联调休（加班费）。
  • 改表：标黄 + 批注，更新工作日/休息日/节假日合计。
5.2 夜班约 3%
  • 顾问月初提供名单；跨天取 Day1 上班卡 + Day2 下班卡。
  • 涉及 MOVA、洗地机测评中心等；系统常误显迟到。
5.3 公出约 3%
  • 有出勤天数无打卡时间 → 索要每日打卡截图。
5.4 迟到 / 5.5 事假追问
  • 迟到：无补卡/请假 → 扣 0.5 天；首次发放不预扣。
  • 事假：问清假别；年假查邮件；填「考勤特殊事项模板」发顾问。

RUN

运行命令
RUN · 编排调用三个下游 skill
# 源数据归档（推荐先做）
uv run python skills/attendance/attendance-data-prep/scripts/prepare_attendance_data.py \
  "${SOURCE_DIR}" "${OUTPUT_DIR}" \
  --base-table <花名册.xlsx>

# 异常审核（阶段 5 之后）
uv run python skills/attendance/attendance-exception-review/scripts/build_exception_review.py \
  "${OUTPUT_DIR}/attachments" "${PAY_PERIOD}" \
  "${OUTPUT_DIR}/exception_review.xlsx" \
  --reference-summary "${OUTPUT_DIR}/reference_roster.xlsx" \
  --config <attendance_config.json>

# 备注生成（终审后）
uv run python skills/attendance/attendance-remarks/scripts/build_attendance_remarks.py \
  "${OUTPUT_DIR}/attachments" "${PAY_PERIOD}" \
  "${OUTPUT_DIR}/attendance_remarks.xlsx" \
  --config <attendance_config.json> \
  --reference-summary "${OUTPUT_DIR}/reference_roster.xlsx"

ACCEPTANCE

闭环验收
  • ✓花名册每人有考勤部门。
  • ✓人头核对记录无未解释差异。
  • ✓首次发放前已完成阶段 3 三项整理。
  • ✓每名员工有「核对无误」或完整问题处理链。
  • ✓有问题员工审核包含改表 + 凭证 + 确认。
⊘

ANTI-PATTERNS & RETRY

反例检查 / 失败重试
✗
未核对花名册人头差异就开始按人发放。
✗
把链接打卡员工（约 20%）硬套飞书打卡流程，不单独分支。
✗
数据员表未统一格式就跳过阶段 3 整理。
✗
员工反馈问题后只改表、不收集凭证或未记录处理链。
失败重试
  • 人头差异无法解释 → 暂停发放，回阶段 1–2 核对花名册与考勤部门。
  • 加班/夜班规则不清 → 先补 rules_catalog_draft.md 再验算，不凭经验改表。
  • 下游 data-prep / exception-review 失败 → 修复输入目录后从失败阶段重跑，不跳过门禁。
  • 凭证缺失 → 标记待追问，不将问题员工当作「核对无误」结案。
⟲
