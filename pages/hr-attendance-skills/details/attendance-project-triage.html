入口 · 分诊

考勤项目分诊

attendance-project-triage
🩺
入口与编排 skills/attendance/
读复杂/耗时考勤项目收集表，把客户按耗时和痛点排序，输出自动化优先级清单，并推荐每个客户该用哪套 skill 组合。它不替你做考勤，只回答「先做谁、怎么组合」。
⚡

TRIGGERS

触发场景
▸手上有一张复杂/耗时考勤项目收集表
▸要决定先自动化哪些客户、先投哪条流水线
▸需要把客户按痛点和耗时打分排序
▸想知道每个客户该进哪几个 skill
↹

INPUT & OUTPUT

输入 / 产出
↘ INPUT · 输入
  • 复杂考勤项目收集表（.xlsx）
  • 客户名 / 员工数 / 耗时 / 痛点列
↗ OUTPUT · 产出
  • 项目分诊：客户·员工数·耗时·痛点标签·是否试点·优先级分·建议 Skill
  • 汇总：项目数·试点数·总耗时·试点耗时·试点客户
🪜

STEPS

处理流程
  1. 1
    定位表头
    找到客户名、耗时、痛点列；找不到先检查表头行，不手工猜列号。
  2. 2
    过滤有效行
    排除 eg、样例行、说明行、空客户行，只留真实客户。
  3. 3
    痛点打标签
    归类：催收/反馈慢、格式不统一、异常缺卡审批、人工汇总誊写、规则复杂、客户系统限制、归档截图验收、账单补贴结算。
  4. 4
    命中试点
    默认试点：追觅 / 珠海基石 / 奥托立夫 / 启云方 / 国家电投，命中即「是」。
  5. 5
    打分 + 建议 skill
    每个有效项目给优先级分、痛点标签和推荐进入的后续 skill。
⇄

PIPELINE

与其他 skill 衔接
→
高优先级客户进入数据流水线 data-prep → exception-review → remarks。
⤳
C 型规则核算客户先做 rule-pack 落规则；A 型走 monthly-reconcile，D 型走 laoqin-monthly。
✓

ACCEPTANCE

闭环验收
  • ✓项目分诊、汇总两个 sheet 均存在。
  • ✓输出项目数等于输入表中有效客户行数，不含样例/说明/空行。
  • ✓试点客户命中后「是否试点」为是，汇总中试点数与名单一致。
  • ✓每个有效项目都有优先级分、痛点标签和建议 skill。
⊘

ANTI-PATTERNS

反例检查
✗
把 eg、样例行、表头说明行计入项目。
✗
耗时单位解析失败后默认为 0，却不提示。
✗
痛点文本含缺卡/截图/规则复杂等关键词，标签却为空。
✗
试点客户名单变更后只改文档不改测试。
⌘

RUN

运行命令
RUN · 运行命令
uv run python skills/attendance/attendance-project-triage/scripts/triage_attendance_projects.py \
  <复杂考勤项目收集表.xlsx> \
  outputs/attendance_project_triage.xlsx
