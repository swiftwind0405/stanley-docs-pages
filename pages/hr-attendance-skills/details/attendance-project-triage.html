考勤项目分诊

attendance-project-triage
🩺
入口与编排 skills/attendance/
读「复杂/耗时考勤项目收集表」，按耗时、痛点和试点范围给客户分诊，输出一份自动化优先级清单，并推荐每个客户后续该进入的考勤自动化 skill 组合。它不替你做考勤，只回答「先做谁、按什么优先级、接哪条流水线」。
⚡

TRIGGERS

触发场景
▸手上有一张复杂/耗时考勤项目收集表，要做考勤项目分诊
▸需要做考勤项目评估，按耗时与痛点给客户排序
▸要决定哪些客户先进入 data-prep / exception-review / remarks 流水线
▸attendance project triage：把收集表转成自动化优先级清单
↹

INPUT & OUTPUT

输入 / 产出
↘ INPUT · 输入
  • 复杂考勤项目收集表（.xlsx）
  • 含客户名、员工数、耗时、痛点等列
  • 固定第一批试点客户名单（脚本内常量）
↗ OUTPUT · 产出
  • 项目分诊 sheet：客户、员工数、耗时、痛点标签、是否试点、优先级分、建议 Skill
  • 汇总 sheet：项目数、试点数、总耗时、试点耗时、试点客户
📤

ARTIFACTS

outputs/attendance_project_triage.xlsx

项目数 · 试点数 · 总耗时 · 试点耗时 · 试点客户列表。
🪜

STEPS

处理流程
  1. 1
    定位列与表头
    找到客户名、耗时、痛点列。找不到时先检查表头行位置，不要手工猜列号。
  2. 2
    过滤有效客户行 GATE
    排除 eg、样例行、说明行、空客户行，只留真实客户。项目数将以此为准——样例/说明行混入会同时污染项目数与试点耗时。
  3. 3
    解析耗时
    解析耗时与单位；解析失败时不要默认为 0 而不提示，应保留原始文本并标记需人工复核。
  4. 4
    痛点打标签
    按 8 类痛点标签归类：催收/员工反馈慢 · 格式/来源不统一 · 异常/缺卡/审批 · 人工汇总/誊写/复制 · 规则复杂 · 客户系统限制 · 归档/截图/验收资料 · 账单/补贴/结算。
  5. 5
    命中试点 + 打分 + 建议 skill
    命中固定试点名单则 是否试点 记「是」；给每个有效项目优先级分、痛点标签和建议进入的后续 skill。

✓

ACCEPTANCE

闭环验收4 条
  • ✓项目分诊 和 汇总 两个 sheet 均存在。
  • ✓输出项目数等于输入表中有效客户行数，不包含样例行、说明行或空客户行。
  • ✓固定试点客户命中后 是否试点 为「是」，汇总 中试点数和试点客户列表一致。
  • ✓每个有效项目都有优先级分、痛点标签和建议 skill；痛点为空时必须能解释原因。

ANTI-PATTERNS

反例检查
✗
把 eg、样例行、表头说明行计入项目。
✗
耗时单位解析失败后默认为 0，却没有提示。
✗
痛点文本明显包含缺卡、截图、规则复杂等关键词，但标签为空。
✗
试点客户名单变更后，只改文档不改测试。
↺

FAILURE & RETRY

失败重试
↻
找不到客户名、耗时或痛点列时，先检查表头行位置，不要手工猜列号。
↻
耗时解析异常时，保留原始文本并输出需人工复核；可先修正输入表后重跑。
↻
试点名单或评分口径变化时，先更新脚本常量和测试，再重新生成工作簿。
⟳

LESSONS

复盘沉淀LESSONS.md
·
新增痛点类型、客户名单变化或耗时表达方式变化时，写入 LESSONS.md；重复出现的表达再提升为脚本规则和测试。
·
样例行、说明行未跳过会污染项目数和试点耗时。
·
痛点标签过少会导致推荐 skill 偏保守，需关注未分类痛点。
