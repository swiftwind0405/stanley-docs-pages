02
配置 · 规则

考勤规则包

attendance-rule-pack
📐
配置与交付 skills/attendance/
把客户考勤口径先落成「可复核规则 workbook + attendance_config.json 草稿」，再交给 attendance-remarks、attendance-exception-review 或客户专属脚本使用。先把规则说清楚、把不确定的写进「待确认」，再算备注。
◧

FLOW TYPES

流程类型 A/B/C/D--flow-type
A数据员宽表型
代表客户：追觅。
B钉钉导出 + 异常凭证型
代表客户：珠海基石、奥托立夫。
C钉钉内置核算 + 书面规则型
代表客户：启云方。
D客户系统 PDF + 确认单型
代表客户：国家电投。
⚡

TRIGGERS

触发场景
▸启云方书面规则 docx 要落成机器可读配置
▸奥托立夫早班/中班/夜班/上海班次规则要书面化
▸国家电投确认单加班费合计公式要确认
▸新客户口径先落成可复核规则，再算备注
↹

INPUT & OUTPUT

输入 / 产出
↘ INPUT · 输入
  • 客户名 client_name
  • 月份 pay_period（YYYYMM）
  • 输出目录 output_dir
  • 客户口径：班次/假别/加班去向/法定日/计薪天
  • 书面规则 docx、顾问确认表
↗ OUTPUT · 产出
  • attendance_config.json —— 给 attendance-remarks 使用的配置草稿
  • attendance_rule_pack.xlsx —— 给顾问/HR 复核的规则参数、异常类型、流程规则和待确认项
🪜

STEPS

处理流程
  1. 1
    选流程类型
    按客户确定 --flow-type 为 A / B / C / D，套对应规则骨架。
  2. 2
    填当月日期口径
    日期、标准计薪天、法定假日、休息日、补班日必须来自当月客户口径，不复用历史月。
  3. 3
    拆解客户规则
    班次、欠工时、加班核算、忘打卡、补签、弹性班次等逐条拆入配置。
  4. 4
    列异常类型与待确认 GATE
    不确定项写进 workbook 的「待确认」，不凭经验补值；待确认不为空时 config 只能当草表。
  5. 5
    产出 config + 规则 workbook
    attendance_config.json 给脚本用，attendance_rule_pack.xlsx 给顾问/HR 复核。
▤

OUTPUTS

产物清单
attendance_config.json
给 attendance-remarks 使用的配置草稿；待确认项关闭后才可作最终规则。
attendance_rule_pack.xlsx
给顾问/HR 复核的规则参数、异常类型、流程规则和待确认项。

使用建议 · 各客户复核重点

ACCEPTANCE

闭环验收
  • ✓attendance_rule_pack.xlsx 中「待确认」不为空时，不能把 config 当成最终规则。
  • ✓日期、标准计薪天、法定假日、休息日、补班日来自当月客户口径。
  • ✓新增客户专属异常类型后，先进入 workbook 复核；稳定后再补脚本规则和测试。
  • ✓未关闭「待确认」项的 config 只能用于草表，不能作为最终规则。（来源 LESSONS）
⊘

ANTI-PATTERNS

反例检查
✗
直接复用历史月份的法定日、休息日或计薪天。
✗
把「待确认」未关闭的 attendance_config.json 当成最终配置运行备注生成。
✗
启云方这类 C 型客户只写假期/加班关键词，却遗漏欠工时、补签、弹性班次和月中催办规则。
✗
国家电投 D 型客户未确认加班费合计公式就回填确认单。
↻

FAILURE & RETRY

失败重试
✗
客户口径不完整时，先生成带「待确认」的规则包，不凭经验补值。
✗
规则 docx 或顾问确认表冲突时，以最新顾问确认表为准，并在 workbook 中保留冲突说明。
✗
生成的 config 导致 attendance-remarks flags 激增时，回到规则包补充关键词和日期口径后重跑。
⊕
