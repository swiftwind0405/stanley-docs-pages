07
交付 · 齐套检查

考勤交付包

attendance-delivery-pack
📦
配置与交付 skills/attendance/
在交付 HR / 顾问 / 客户 / 科服前，检查 outputs/<目录名> 是否齐套。不替代业务审核，只把「缺什么文件、能不能交付」变成 Excel 清单。
◧

FLOW TYPES

流程类型 A/B/C/D
A型
追觅类宽表：员工清单 + 异常审核 + 考勤备注
B型
凭证型：来源归一 + 异常审核 + 考勤备注
C型
启云方规则核算：规则包 + 规则配置 + 异常审核
D型
国家电投：员工清单 + 确认单 + 劳勤 PDF
⚡

TRIGGERS

触发场景
▸月底交付前检查包是否齐套
▸想知道差哪些文件、哪些已可交付
▸按 A/B/C/D 型生成交付清单
↹

INPUT & OUTPUT

输入 / 产出
↘ INPUT · 输入
  • outputs/<目录名>（各上游产物）
  • --flow-type A/B/C/D
↗ OUTPUT · 产出
  • delivery_pack.xlsx：交付清单 · 问题清单 · 汇总（是否可交付）
🪜

STEPS

处理流程
  1. 1
    选流程类型
    按 A/B/C/D 选对应交付项集合。
  2. 2
    比对期望文件
    每个交付项的期望文件、状态、匹配文件逐项核对。
  3. 3
    列问题清单
    缺失项 + 建议动作，指回对应上游 skill。
  4. 4
    出汇总
    交付项数、缺失项数、是否可交付。
⇄

PIPELINE

与其他 skill 衔接
←
汇总 data-prep / normalizer / exception-review / remarks 的产出。
⤳
缺失项回到对应上游 skill 补齐后重跑交付检查。
✓

ACCEPTANCE

闭环验收
  • ✓汇总中「是否可交付」为是之前，不直接提交最终包。
  • ✓D 型必须同时有员工 PDF 和确认单；只有 PDF 不算闭环。
  • ✓B 型必须先跑 source-normalizer，否则凭证来源无法审计。
⊘

ANTI-PATTERNS

反例检查
✗
D 型只有劳勤 PDF，没确认单或确认单未签回。
✗
B 型只有 attendance_remarks.xlsx，没来源归一和异常审核。
✗
C 型只有规则包，没异常审核或催办闭环记录。
✗
文件存在但属历史月份，被误当成本月交付物。
⌘

RUN

运行命令
RUN · 运行命令
uv run python skills/attendance/attendance-delivery-pack/scripts/build_delivery_pack.py \
  outputs/<目录名> outputs/<目录名>/delivery_pack.xlsx \
  --flow-type B
