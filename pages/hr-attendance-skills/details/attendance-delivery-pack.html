07
交付 · 齐套检查

考勤交付包

attendance-delivery-pack
📦
配置与交付 skills/attendance/
在交付 HR / 顾问 / 客户 / 科服前，检查当前 outputs/<目录名> 是否已齐套。本 skill 不替代业务审核，只负责把「缺什么文件、哪些资料可交付」变成 Excel 清单。
◧

FLOW TYPES

流程类型 A / B / C / D--flow-type
A追觅类
数据员宽表：需要员工清单 + 异常审核 + 考勤备注。
B凭证型
珠海基石 / 奥托立夫类：需要来源归一 + 异常审核 + 考勤备注。
C规则核算型
启云方类：需要规则包 + 规则配置 + 异常审核。
DPDF+确认单型
国家电投类：需要员工清单 + 确认单 + 劳勤 PDF（2026-06 起客户侧不含 PDF，转内部留存）。
⚡

TRIGGERS

触发场景
▸交付 HR / 顾问 / 客户 / 科服前，确认包是否齐套。
▸想知道缺什么文件、哪些资料已经可以交付。
▸按 A / B / C / D 型生成本月交付清单。
↹

INPUT & OUTPUT

输入 / 产出
↘ INPUT · 输入
  • outputs/<目录名>：各上游 skill 已落地的产物
  • --flow-type A / B / C / D
↗ OUTPUT · 产出
  • delivery_pack.xlsx：交付清单 · 问题清单 · 汇总三个 sheet
▦

OUTPUT SHEETS

delivery_pack.xlsx 产物
交付清单
每个交付项、期望文件、状态、匹配文件。
问题清单
缺失项和建议动作。
汇总
交付项数、缺失项数、是否可交付。
🪜

STEPS

处理流程
  1. 1
    选流程类型
    按 A / B / C / D 选对应交付项集合。
  2. 2
    比对期望文件
    每个交付项的期望文件、状态、匹配文件逐项核对，写入「交付清单」。
  3. 3
    列问题清单
    缺失项 + 建议动作，指回对应上游 skill。
  4. 4
    出汇总GATE
    交付项数、缺失项数、是否可交付；「是否可交付」为「是」前不直接提交最终包。
⇄

PIPELINE

与其他 skill 衔接
←
汇总 source-normalizer / exception-review / remarks 等上游产物，判断 outputs/<目录名> 是否齐套。
⤳
缺失项回到对应上游 skill 补齐后，重跑交付检查。
✓

ACCEPTANCE

闭环验收
  • ✓「汇总」中「是否可交付」为「是」前，不应直接提交最终包。
  • ✓D 型客户内部留存须同时有员工 PDF 和确认单；客户侧闭环以考勤表 + 确认单签字回流为准（国家电投 2026-06 起客户侧不含劳勤 PDF）。
  • ✓B 型客户必须先跑 attendance-source-normalizer，否则凭证来源无法审计。
⊘

ANTI-PATTERNS

反例检查
✗
D 型客户只有劳勤 PDF，没有确认单或确认单未签回。
✗
B 型客户只有 attendance_remarks.xlsx，没有来源归一和异常审核。
✗
C 型客户只有规则包，没有异常审核或催办闭环记录。
✗
文件存在但属于历史月份，被误当成本月交付物。
⌘

RUN

运行命令
RUN · 运行命令
uv run python skills/attendance/attendance-delivery-pack/scripts/build_delivery_pack.py \
  outputs/<目录名> \
  outputs/<目录名>/delivery_pack.xlsx \
  --flow-type B
↻

RETRY

失败重试
↻
缺失项出现时，回到对应上游 skill 补齐后重跑交付检查。
↻
文件命名不含默认关键词时，先人工确认路径，再决定是否扩展交付匹配规则。
↻
交付包显示可交付但业务仍有待追问时，优先以 exception-review / remarks 的待追问为准。
✦

LESSONS

复盘沉淀
  • !齐套检查只能证明文件存在，不能替代业务口径审核；待追问和异常审核仍是最终交付前的门禁。
  • !新增交付项、客户专属签回文件或误匹配模式写入 LESSONS.md；稳定后再补默认检查项和测试。
