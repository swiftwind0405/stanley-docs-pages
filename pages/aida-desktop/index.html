AidaWork Desktop — Architecture Visual Pack

Source-grounded architecture briefing · 6 perspectives · aida-desktop (Electron + Vite + React)

Verdict

A typed-IPC Electron host where a trusted React renderer streams chat over SSE and a server orchestrator delegates high-risk local tool calls to a TTL-governed, approval-gated hybrid local executor — security-conscious and well-layered, but several execution-isolation and runtime-spawn boundaries remain unconfirmed.

System Map

The application is a single Electron host split across three trust zones. The main process is the composition root: it owns 12 typed IPC namespaces (30 invoke + 8 push channels) wired through shared/ipc-contract.ts, plus the auth/token exchange, config store, hybrid local executor, document intake, update lifecycle, speech helper, and BI insight channel. The preload layer bridges only a derived, narrow surface (aidaDesktop for the trusted UI; __aidaBiBridge for the untrusted ChatBI guest). The renderer composes the HR workbench shell, the chat logic layer (src/chat/core), and presentational surfaces.

Cross-cutting spine: a shared TtlRegistry backs every pending-decision state machine (write approvals, transient file grants, document intake, extraction jobs). Token identity is bound to an endpoint identity (origin + basePath). Chat is scoped by a derived chat identity (tenantId:userId). The six diagrams below traverse this from process topology down to the individual state machines.
