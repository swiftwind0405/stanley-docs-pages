Model-invoked 与 user-invoked

本 repo 中每个 SKILL.md 都是一个 skill。划分它们的唯一轴是 invocation——谁可以调用它：

  • User-invoked——仅当你输入其名称时可调用。在 frontmatter 中设置 disable-model-invocation: true。description 面向人类：浏览 slash 命令时阅读的一行摘要。去掉触发列表（「Use when the user says…」）。
  • Model-invoked——模型或用户均可调用。默认：省略 disable-model-invocation。description 面向模型，保留丰富的触发措辞（「Use when the user wants…, mentions…, asks for…」），以便自动调用。判断 skill 是否应保持 model-invoked 的测试：模型能否在合适时自主调用它？（复用是提取 skill 的理由，不是测试标准。）

因为 user-invoked skill 没有 description，除人类外 nothing 能调用它——其他 skill 无法触发它。因此 user-invoked skill 可以调用 model-invoked skill，但 never 调用另一个 user-invoked skill。

Bucket 的 README.md 与顶层 README.md 将条目分为 User-invoked 与 Model-invoked 两组。

二者之间的依赖

依赖以 /skill 式 prose 调用表达（「Run the /grilling skill」），而非 ../other-skill/FILE.md 式 deep 交叉引用。共享 reference 文档放在拥有它的 skill 内部；其他 skill 通过调用该 skill 来触及材料，而非跨文件夹链接。

被动 vs 主动领域工作

仅 读取 CONTEXT.md 获取词汇是一行 prose 指针，不是 domain-modeling skill。只有主动的 build/sharpen 纪律（挑战术语、边缘场景、写 ADR、inline 更新 CONTEXT.md）才是 domain-modeling。
