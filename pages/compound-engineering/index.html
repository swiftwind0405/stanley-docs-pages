Compound Engineering 技能文档

面向使用者的技能介绍：每个斜杠命令的用途、机制、用例与在工程循环中的位置。共 39 个技能。

核心工程循环

   [/ce-ideate]       （可选）「值得探索什么？」
        │
        ▼
┌─→ /ce-brainstorm    「这应该成为什么？」
│       │
│       ▼
│   /ce-plan          「如何达成目标？」
│       │
│       ▼
│   /ce-work          「动手实现。」
│       │
│       ▼
└── /ce-compound      「沉淀所学。」

/ce-compound 将学习写入 docs/solutions/，供下一轮 /ce-brainstorm 与 /ce-plan 读取——这就是「compound」的含义。

核心循环

/ce-brainstorm

定义某些东西应该变成什么——协作对话、命名间隙透镜、适当大小的需求文档

 /ce-compound

通过将您所学到的内容捕获到 `docs/solutions/` 中来关闭循环，以便下一次迭代开始更智能 — bug 跟踪 + 知识跟踪

 /ce-ideate

*可选的第一步*——通过六个概念框架、保证要求、对抗性过滤发现值得探索的强大、合格的方向

 /ce-plan

带有护栏的绑定执行——U-ID、测试场景、自动置信度检查；做什么决定，而不是如何编码

 /ce-work

对照计划的护栏执行——用你面前的代码找出如何通过质量关口的交付

循环

/ce-compound-refresh

随着时间的推移维护 `docs/solutions/` — 五种结果（保留/更新/合并/替换/删除），交互 + 自动修复模式

 /ce-product-pulse

外部反馈循环——关于使用情况、性能、错误、后续行动的单页时间窗口报告；作为时间线保存到 `docs/pulse-reports/`

 /ce-strategy

创建或维护 `STRATEGY.md` — 由 `ce-ideate`、`ce-brainstorm` 和 `ce-plan` 读取的上游锚点作为接地

一经请求

/ce-code-review

使用分层角色代理进行结构化代码审查、置信门控结果、四种模式

 /ce-debug

系统地查找根本原因——因果链门、不确定环节预测、智能升级

 /ce-doc-review

使用平行角色代理审查需求或计划文档 - 一致性、可行性、产品镜头、设计镜头、安全镜头、范围守护者、对抗性

 /ce-optimize

指标驱动的迭代优化循环——三层评估、并行实验、持久性规则

 /ce-simplify-code

优化最近更改的代码——三个并行审阅者代理（重用、质量、效率）；行为保存已验证

研究与背景

/ce-riffrec-feedback-analysis

将原始 [Riffrec](https://github.com/kieranklaassen/riffrec) 录音转化为结构化反馈 - 通过 `ce-brainstorm` 切换进行快速错误或广泛分析

 /ce-sessions

在 Claude Code、Codex 和 Cursor 中搜索会话历史记录，以获取与问题相关的上下文

 /ce-slack-research

在 Slack 中搜索解释的组织环境 — 工作空间身份、研究价值评估、横切分析

Git 工作流程

/ce-clean-gone-branches

删除远程跟踪分支已消失的本地分支，包括任何关联的工作树

 /ce-commit

创建一个精心设计的 git 提交 — 约定感知、敏感文件安全、文件级逻辑拆分

 /ce-commit-push-pr

从工作变更到具有自适应描述的开放 PR — 三种模式（完整工作流程/描述更新/仅描述生成）

 /ce-worktree

使用 `.env` 复制、分支感知开发工具信任和 gitignore 管理在 `.worktrees/<branch>` 创建 git 工作树

前端设计

/ce-frontend-design

构建具有真正设计质量的 Web 界面 - 上下文检测、视觉论文预构建、固执己见的默认值、视觉验证

 /ce-polish

会话式用户体验优化——启动开发服务器，打开浏览器，一起迭代；自动检测 8 个框架（仅限手动调用）

合作

/ce-proof

通过 [Proof](https://www.proofeditor.ai)、Every 的协作编辑器 — Web API 和 Local Bridge 界面，在 Markdown 上创建、共享和运行人机交互审阅循环

工作流程实用程序

/ce-demo-reel

捕获 PR 描述的视觉证据（GIF、终端录音、屏幕截图）——与测试输出严格分离

 /ce-promote

为已发布的功能（X、变更日志、LinkedIn、电子邮件）起草面向用户的公告副本 - 通过可选的 Spiral CLI 进行语音匹配，这是一个精简的编辑和社交专业知识层，没有它，仅草稿

 /ce-release-notes

查找最近的复合工程插件版本中包含的内容 - 摘要或带有版本引用的具体问题

 /ce-report-bug

报告复合工程插件中的错误 - 结构化摄入、自动环境收集、GitHub 问题创建

 /ce-resolve-pr-feedback

并行评估、修复和回复公关审查反馈——包括挑剔

 /ce-setup

诊断环境、安装缺少的工具、引导项目本地配置 — 在一个流程中进行交互式入门

 /ce-test-browser

专门使用 `agent-browser` 对 PR / 受分支影响的页面进行端到端浏览器测试

 /ce-test-xcode

使用 XcodeBuildMCP 在模拟器上构建和测试 iOS 应用程序 — 屏幕截图、日志、人工验证

 /ce-update

根据 `main` 检查已安装的复合工程插件版本并推荐更新命令（仅限克劳德代码）
