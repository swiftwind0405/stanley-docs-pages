ce-slack-research

在 Slack 中搜索解释的组织环境 — 塑造当前任务的决策、约束和讨论弧。研究摘要，而不是原始消息列表。

ce-slack-research 是组织上下文检索技能。它派遣 ce-slack-researcher 在 Slack 中搜索与主题相关的上下文，然后通过横切分析和研究价值评估综合研究摘要，而不是简单的消息命中列表。在计划、头脑风暴或团队已经讨论过某些内容并且代理需要上下文才能提出合理建议的任何任务时非常有用。

与 slack:find-discussions （一种不同的技能，返回单个消息结果而不进行综合）不同：此技能解释发现的内容。

TL;DR

问题 回答
它有什么作用？ 搜索 Slack 的主题并返回综合研究摘要，其中包含工作空间身份、价值评估、主题发现和横切分析
何时使用它 在计划或集思广益之前，当“我们之前在 Slack 中讨论过这个问题”时，首先了解上下文，然后继续
它生产什么 摘要：工作空间标识符、研究价值评估（高/中/低/无）、按主题组织的发现、横切分析
关键对比 ce-slack-research 综合； slack:find-discussions 返回原始消息命中

＃＃ 问题

Slack 是一种团队拥有但很少使用的工作记忆：

  • 决定隐藏在旧线程中 - “我们在二月份决定了 X 关于定价”是在一个没人记得的频道中
  • 约束存在于私下对话中 - 功能范围缩小的原因不在规范中，而是在 DM 中
  • 原始搜索返回噪音 — slack:find-discussions 找到消息，但不会告诉您如何处理它们
  • 错误的工作空间风险 - 搜索错误的 Slack 实例会产生听起来自信但不相关的上下文
  • 讨论弧丢失 - 单个线程可能会持续 3 天；一条消息点击并不能显示对话的进展情况
  • 没有价值评估 - 谈话有结论吗？投机？决定了吗？如果没有这个信号，代理就无法适当地权衡结果

解决方案

ce-slack-research 通过研究型管道运行 Slack 搜索：

  • 工作空间标识符浮出水面 — 用户可以在阅读结果之前验证是否搜索了正确的 Slack 实例
  • 研究价值评估 — 高/中/低/无，并有理由
  • 按主题组织的调查结果 — 不是平面消息列表；按来源渠道和日期的内容进行聚类
  • 跨领域分析 — 跨结果的模式，而不仅仅是每条消息的摘要
  • 单发派遣 — 该技能是一个薄弱的切入点； ce-slack-researcher 执行实际工作（MCP 发现、搜索执行、线程读取、综合）

是什么让它如此新颖

1. 综合，而非搜索

代理不返回匹配的消息。它返回一个具有结构的摘要：

  • 工作区标识符 — 搜索了哪个 Slack 工作区（以便用户可以纠正错误）
  • 研究价值评估 — 研究结果实际上有多大用处，并有理由：
    • 高 — 与主题相关的结论性决定或严格限制
    • 中等 — 与主题相关但不是结论性的上下文
    • 低 — 无关的提及或微弱的信号
    • 无 — 没有相关发现；该话题尚未讨论
  • 按主题组织的调查结果 - 具有源渠道和日期的集群
  • 横切分析 - 每个消息视图错过的发现的模式

2.工作区身份验证

Slack 搜索中的一个常见失败模式是搜索错误的工作区并获得确信不相关的结果。该技能首先显示工作区标识符，以便用户可以验证是否搜索到了正确的 Slack 实例。如果代理连接到个人 Slack 工作空间而不是公司工作空间，那么就会在摘要将任何人引入歧途之前捕获它。

3. 具有合理性的研究价值评估

研究结果并不同样有用。一个达成共识的、已决定的产品问题与一个投机性的周末切题的权重不同。代理评估语料库并解释评级 - “高：2026 年 3 月 12 日在 #proj-billing 中明确决定，有三位批准者”或“低：#general 中一次提及；未积极讨论主题”。

4. Slack 搜索修饰符直通

输入可以是关键字、自然语言问题，或包含 Slack 搜索修饰符：

  • 频道提示：in:#proj-reverse-trial
  • 日期过滤器：after:2026-03-01、before:2026-04-15
  • 短语搜索、排除等。

代理提取主题并根据输入的任何形式制定搜索。

5. 瘦编排器，代理完成工作

该技能本身是一个简单的入口点，如果没有给出主题，则询问主题，然后分派 ce-slack-researcher。该代理处理 MCP 发现、搜索执行、线程读取和综合。这使得面向用户的表面很小，而繁重的工作则由专业代理完成。

6. 与原始搜索 Slack 工具不同

slack:find-discussions（不同的技能）返回适合“最近有人提到 X 吗？”的单独消息结果。 ce-slack-research 返回适合“团队对 X 有何看法，有什么证据？”的解释上下文。区别很重要——使用错误的工具会带来噪音。

7. 故障模式清晰地浮出水面

如果 Slack 不可用（MCP 未连接或身份验证已过期），代理会清楚地报告该情况，并且技能会中继该消息。它不会尝试其他研究方法或假装进行过搜索。如果用户想要其他地方的上下文，那就是不同的调用。

简单示例

您即将计划免费试用功能。在撰写头脑风暴之前，您想知道团队已经讨论过什么。您调用 /ce-slack-research "free trial in #proj-reverse-trial"。

该技能会调度 ce-slack-researcher 以及主题、通道范围和隐式最近窗口。该代理连接到配置的 Slack 工作区，在 #proj-reverse-trial 中运行有针对性的搜索，扩展相关线程并综合结果。

摘要返回：

  • 工作空间： every.slack.com
  • 研究价值： 高 — 与免费试用范围相关的多项决策和限制
  • 调查结果：
    • 试用长度： 在 30 天因漏斗数据太长而被拒绝后决定 14 天默认（2026 年 3 月 12 日线程中的决定，三名批准者）
    • 转换门： 软付费墙优于硬付费墙；未解决该门是在注册时触发还是在首次使用后触发
    • **试用期间的定价：**一致“不显示定价” - 出现在三个不同的线程中
  • 跨领域分析： 该团队始终倾向于转换保护（试用期间不定价，软门），但尚未在转换门时序上达成共识。这是值得在头脑风暴中解决的实时问题。

现在，在调用 /ce-brainstorm 之前，您已经拥有了真实的组织上下文。头脑风暴从“试用期为 14 天、软付费墙、没有可见的定价——大门什么时候启动？”开始。而不是从头开始。

何时去实现它

在以下情况下使用 ce-slack-research：

  • 您即将计划或集思广益团队在 Slack 中讨论过的事情
  • 存储库/文档对决定保持沉默，但团队显然做出了决定
  • 存在约束（“我们不能使用该供应商”），但其基本原理是在某个线程中
  • 您需要解释上下文，而不是原始消息命中

在以下情况下跳过 ce-slack-research：

  • 您想要原始消息命中 → 使用 slack:find-discussions
  • 上下文在代码或文档中→改为阅读它们
  • 该主题太新，尚无 Slack 历史记录
  • 您没有配置 Slack 工具 → 首先设置 Slack MCP

用作工作流程的一部分

当组织环境很重要时，ce-slack-research 插入规划和头脑风暴的上游：

  • 在 /ce-brainstorm 之前 — 收集 Slack 上下文，以便头脑风暴的压力测试问题能够扎根于真正的事先讨论
  • 在 /ce-plan 之前 — 当工作涉及团队在其他地方做出的决定时，首先浮出该决定
  • 从内部 /ce-plan 阶段 1.1 — 通过“检测到 Slack 工具；要求我在 Slack 中搜索组织上下文”选择加入
  • 从内部 /ce-brainstorm 阶段 1.1 — 通过相同的表面图案选择加入
  • 从内部 /ce-ideate 第 1 阶段 — 选择加入松弛研究以实现构思基础步骤

当链技能检测到 Slack 工具时，它们就会显示可用性，但不会自动调度——用户选择加入。

使用独立版

大多数使用是直接的：

  • 主题 — /ce-slack-research free trial
  • 问题 — /ce-slack-research "What did we say about free trial recently?"
  • 频道范围 — /ce-slack-research free trial in:#proj-reverse-trial
  • 日期过滤 — /ce-slack-research onboarding flow after:2026-03-01
  • 没有争论 — /ce-slack-research 询问要研究什么主题

该技能接受您的主题自然呈现的任何形式——关键字、问题，带或不带 Slack 搜索修饰符。

＃＃ 常问问题

这和 slack:find-discussions 有什么区别？ slack:find-discussions 返回单个消息结果 - 对于“最近有人提到 X 吗？”很有用ce-slack-research 解释和综合 — 对于“团队如何看待 X，有什么证据？”很有用。使用正确的工具来解决问题。

为什么它会显示工作区标识符？ 因为搜索错误的 Slack 工作区会产生与自信无关的结果，并且用户通常无法仅从结果中判断。显示工作区标识可以让用户在阅读摘要之前捕获错误的工作区情况。

研究价值评估是什么意思？ 对研究结果实际有用程度的判断。 高=结论性决策/强约束。 中等 = 与主题相关但不是结论性的。 低 = 信号弱。 无 = 该主题尚未得到有意义的讨论。理由解释了评级。

它可以搜索私人DM吗？ 取决于配置的 Slack MCP 公开的内容。该技能没有自己的访问权限——它使用 MCP 允许的任何内容。对于私有内容，请确保 MCP 具有正确的范围。

如果工作空间不合适怎么办？ 该技能首先显示工作区标识符，以便用户可以根据需要验证并重新调用不同的工作区标识符。如果配置了多个工作区，代理会选择连接的工作区；用户消除歧义。

没有 Slack MCP 也能工作吗？ 不会。如果无法访问 Slack 工具，代理会清楚地报告不可用性，并且技能会转发该信息。这项技能不会退回到其他研究方法——否则会产生错误的结果。
