aida-agent — Architecture Visual Pack

Source-grounded briefing · 5 perspectives · generated 2026-06-14 · read-only

Verdict

aida-agent is a pre-production, single-process Hono orchestrator whose backbone — dual-token auth, capability-first routing, a persistence-backed ReAct loop, write-governance via Action Proposals, and blocking high-risk audit — is clearly grounded in code and ADRs; its runtime risks are concentrated almost entirely in unverified production topology (no Dockerfile/k8s/wrangler in repo) and in encryption-key-rotation / cross-tenant-isolation enforcement details.

System Map

Five perspectives over one codebase. Each diagram is independently sourced; together they trace a request from token to Postgres, the routing/orchestration brain that decides what runs, where processes live, how permission boundaries hold, and how durable state transitions are governed.

1 · Data Flow

One /api/chat request lifecycle: Aida JWT → Gateway → session binding → ReAct loop → SSE events → Postgres + audit.

2 · Agent Orchestration

Capability-first router pipeline, the shared ReAct loop, tool gating/risk, child-run agent-as-tool, and local workbench dispatch.

3 · Deployment

Dev/local process topology and external dependencies. Production topology is not present in the repo.

4 · Permissions

Dual-token boundary, write governance via Action Proposals, blocking-audit safety gates, route-decision encryption + admin access.

5 · State Machines

ActionProposal, PendingInteraction, and CapabilityRoute status lifecycles and their cross-coupling.
